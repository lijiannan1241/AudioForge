有声书交付前，我必查的 7 个数字

不是"听起来还行"，而是"这七个指标都合格"。交付前花十分钟，能省掉一次返工。

2026-11-17 · 约 1343 字符

English version → English

有声书的返工成本极高：改一个参数，可能意味着九小时的合成白跑。所以交付前必须有一张检查表——不是凭感觉听一遍，而是看七个数字。

1. 整体响度：-19 LUFS（±0.5）

有声书的目标通常定在 -19 LUFS，比播客（-16）留更多余量，因为在安静环境里长时间收听，过响会疲劳。

看哪里：批处理报告里的「输出 LUFS」列。要看的不是单条是否合格，而是整批的离散度——如果有几条落在 -21，说明底稿本身的动态差异没被处理好。

2. 真峰值：不高于 -1 dBTP

MP3/AAC 编码会带来过冲，母带阶段卡在 -1 dBTP，编码后才不会削顶。

看哪里：报告的「真峰值(dB)」列。注意这里是 dBTP（真峰值），不是采样峰值——两者能差 1 dB 以上，用采样峰值判断会漏。

3. 削波样本数：0

任何非零都意味着波形顶部被削平了，听感上是"破"。削波是不可逆的，只能回退源头重做。

看哪里：报告的「削波样本」列。这一列不需要理解，只需要等于 0。

4. DC 偏移：接近 0

直流偏移会让波形整体偏离中线，浪费动态余量，某些播放器还会产生咔哒声。老录音、某些声卡采集的文件尤其常见。

看哪里：报告列 + 波形图。波形明显不对称就该处理。

5. 章节时长与语速离群

一章 47 分钟、下一章 3 分钟，很可能不是作者写得短，而是分章或 OCR 出了问题。

看哪里：章节列表的「字符数 / 时长 / 状态」，以及 TTS 报告里的语速离群规则。发现 3 秒的章节，先回去看那一页的识别结果。

6. 静音占比

静音占比过高（比如超过 30%），说明底稿里有大量空白页、目录页、或者断裂的段落。听众的实际体验是"一直在等下一句"。

看哪里：TTS 专项 QA 报告。

7. 未被词典覆盖的发音

缩写、型号、人名——全大写缩写和长数字串是最容易念错的两类。词典没覆盖到，机器就会按默认规则硬念。

看哪里：TTS 报告会列出未被发音词典覆盖的全大写缩写与长数字串。补完词典，重合成受影响的那几章即可（断点续传只补改动块）。

附：交付物清单

  • M4B 主文件：AAC、章节轨、封面、书名/作者元数据齐全；
  • 章节音频（可选）：一章一个文件，方便二次剪辑；
  • 报告：CSV + HTML 各一份，给客户或存档；
  • 命名规范：书名_章节号_标题.m4b 这类可排序的名字，别用"最终版2真的最终"。

最后一件小事

用播放器真的听一遍第一章，并且试着跳一次章。跳章失败、封面不显示、进度不记忆——这些问题在报告里全是绿的，只有 listener 会遇到。

七个数字都对，不代表作品好听；但七个数字里有任何一个不对，就一定会有听众听出来。
